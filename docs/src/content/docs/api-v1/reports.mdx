QuestLab does not only record that a student *finished*. It records **what they answered, how many tries it took, and what evidence they produced** for each thing the mission set out to teach. The reports below give you that at four levels: one assignment, one student, a mission across classes, and your whole organization.

All of them need `reports:read` (chat messages need `messages:read`). Students appear by `student_id`, `external_id` and pseudonym. The organization-wide reports take the filters `school_id`, `teacher_id` and `grade_level`.

| You want to know | Use |
| --- | --- |
| How is this class doing on this assignment? | [`GET /assignments/{id}/report`](#one-assignment) |
| What goes in the gradebook? | [`GET /assignments/{id}/grades`](#grades-for-a-gradebook) |
| How is this student doing overall? | [`GET /students/{id}/report`](#one-student) |
| Which questions do students find hard, and what do they wrongly answer? | [`GET /reports/learning`](#learning-across-missions) |
| Which standards have we actually taught? | [`GET /reports/standards`](#standards-coverage) |
| Who is using QuestLab, how often, for how long? | [`GET /reports/engagement`](#engagement) |
| A one-glance picture for the district | [`GET /reports/summary`](#summary) |

The parts that matter most to a teacher:

- **`questions[]`**: for every question the student met, how many `attempts` and the `first_answer` and `last_answer`. Where the mission's author [marked the right answers](/docs/editor/infoboxes/#marking-right-and-wrong-answers), you also get `first_answer_correct` and `last_answer_correct`.
- **`learning[]`**: the **evidence** each learning objective recorded for this student. This is the field to read if you care about understanding, not completion.
- **`time_spent`** is in seconds; **`scenes_visited`** and **`scene`** show where they went and where they stopped.

## Grades for a gradebook

```http
GET /api/v1/assignments/2/grades
GET /api/v1/assignments/2/grades?format=csv
```

One row per student, shaped for a gradebook:

```json
{
  "student_id": 92153,
  "external_id": "5e11ab1e",
  "display_name": "Happy Gecko 452",
  "team": "Rockets",
  "status": "completed",
  "score": 82,
  "score_parts": { "objectives": 100, "accuracy": 40, "vocabulary": 80 },
  "objectives_done": 6,
  "objectives_total": 6,
  "questions_answered": 5,
  "answered_first_try": 2,
  "words_learned": 4,
  "words_total": 5,
  "time_spent": 2300,
  "started_at": "2026-11-20T14:22:41+00:00",
  "completed_at": "2026-11-20T14:46:51Z",
  "late": false,
  "missing": false
}
```

`status` is `not_started`, `in_progress` or `completed`. `score` is 0 to 100, and `null` until the student has started. Use `external_id` to match the row to your gradebook. [How the score is worked out](#how-the-numbers-are-worked-out) is below, and **you can ignore it entirely** and compute your own grade from `score_parts` or the report.

<Aside type="tip">
A score is a convenient summary, not the point. The questions a student got stuck on and the evidence they produced say far more about what they understood than 82 does. [Using the reports to teach](/docs/educators/maximize-learning/#3-use-the-evidence-not-just-the-score) shows how teachers use them.
</Aside>

## Learning across missions

```http
GET /api/v1/reports/learning?from=2026-09-01&to=2026-12-20
```

Per mission (for assignments made between `from` and `to`, or for one `scenario_id`): how many students started and finished, the average score and time, each objective's completion rate, and **each question's first-answer distribution**. That last one is the report a department head should look at:

```json
{
  "action_id": "134069",
  "prompt": "…",
  "students": 5,
  "average_attempts": 1.2,
  "first_try_rate": 0.8,
  "first_answer_correct_rate": null,
  "first_answers": [
    { "answer": "It gives us something to compare the sick plants with", "students": 4 },
    { "answer": "Healthy plants are easier to carry", "students": 1 }
  ]
}
```

When many students choose the same *wrong* first answer, you have found a common misconception, and a teacher can address it in the next lesson. (`first_answer_correct_rate` is filled in when the author marked which answers are right.)

Each learning objective also reports its evidence rate and the values students recorded:

```json
{
  "id": "lo-evidence",
  "text": "Use evidence from tests to identify the source of a contaminant",
  "standards": ["MS-LS2-4"],
  "students_with_evidence": 6,
  "values": {
    "source-report.first_answer": { "Something in their surroundings is damaging them": 3, "unanswered": 3 },
    "source-report.tries": { "1": 3 }
  },
  "evidence_rate": 1
}
```

## Standards coverage

```http
GET /api/v1/reports/standards
```

Which standards your missions address, which missions address them, how many students were taught each, and how they did. It is the `standards` part of the learning report on its own.

```json
{
  "code": "MS-LS2-4",
  "framework": null,
  "description": null,
  "alignment": "primary",
  "scenarios": [3],
  "students": 6,
  "completion_rate": 0.333,
  "average_score": 70.6
}
```

`framework` and `description` are filled in when the mission's author gave them. Where the author entered only a code, they are `null`.

## Engagement

```http
GET /api/v1/reports/engagement?from=2026-10-22&to=2026-11-21&timezone=America/Denver&interval=day&group_by=school
```

Who took part, how often and how long. It defaults to the last 30 days.

| Parameter | Meaning |
| --- | --- |
| `from`, `to` | The period. Default: the last 30 days. |
| `timezone` | IANA name, for where days begin. Default UTC. |
| `interval` | `day` or `week`, for the `series`. |
| `group_by` | `school`, `grade_level` or `teacher`, adds `groups`. |
| `include=students` | A row per student too (or `format=csv` for just those rows as CSV). |

```json
{
  "data": {
    "period": { "from": "2026-10-22T00:00:00-06:00", "to": "2026-11-21T00:00:00-07:00", "timezone": "America/Denver", "interval": "day" },
    "totals": {
      "students": 7, "active_students": 5, "participation_rate": 0.714,
      "sessions": 5, "active_minutes": 99, "actions": 81, "messages": 1,
      "average_minutes_per_active_student": 19.8,
      "average_sessions_per_active_student": 1,
      "average_active_days_per_active_student": 1
    },
    "series": [ { "start": "2026-11-20", "active_students": 5, "sessions": 5, "active_minutes": 99, "actions": 81 } ],
    "groups": [
      {
        "school_id": 2, "students": 6, "active_students": 5, "participation_rate": 0.833,
        "sessions": 5, "active_minutes": 99, "actions": 81, "messages": 1,
        "average_minutes_per_active_student": 19.8
      }
    ]
  }
}
```

`series` is one entry per day or week: the trend to chart. (The listing above shows only the busy day; the real answer has an entry for every day in the period.) `groups` appears with `group_by`, one entry per school, grade level or teacher. With `include=students` and `format=csv` you get one row per student:

## What students did, in order

Two more endpoints give raw activity: `GET /assignments/{id}/activity` (what students did in one assignment, newest first) and the organization-wide [activity feed](/docs/api-v1/activity-and-privacy-requests/#the-activity-feed) for your data warehouse. The chat transcript of an assignment is `GET /assignments/{id}/messages`, with `messages:read`.

## How the numbers are worked out

<Host who="sam" side="right">
No black boxes. Here is every formula behind every number, so you can explain a grade to anyone.
</Host>

None of this is hidden. Everything below is how QuestLab computes the figures, so you can reproduce them or choose to ignore them.

- **Time spent** is the game's own clock for the student's save in that game (seconds actually in the mission, not minutes the tab was open).
- **Sessions and active minutes** (engagement) come from the activity log. A gap of more than **15 minutes** between two things a student did starts a new session; a session lasts from its first to its last line, and at least one minute.
- **Active student**: did anything in the period. **Participation rate**: active students ÷ students with active status in the population.
- **Actions**: hotspots used, answers chosen, objectives completed, words learned and awards earned.
- **First try**: a question answered once. Missions usually ask again until the answer is right, so one attempt usually means right first time. Where the author marks answers (`"correct": true` or `false` on an infobox's `call_to_actions`), the report also gives `first_answer_correct`, and the score uses it.
- **Score** (0 to 100) = **60% objectives** (required objectives done ÷ required objectives) + **25% accuracy** (first answers right, or the first-try rate where answers are not marked) + **15% vocabulary** (glossary words learned ÷ words). A part the mission does not have is left out and the others share its weight. No score until the student has started.

  Worked through for the student above: 100% of objectives × 0.60 = 60, 40% accuracy × 0.25 = 10, 80% vocabulary × 0.15 = 12. Total 82.
- **Completed**: every required objective done. **Late**: completed after `due_at` (judged at the time the last objective was completed). **Missing**: past `due_at` and not completed.
- **Learning objectives' evidence** is whatever the mission's author recorded in variables for each learning objective, with each student's values. Reports count how many students produced each value.
