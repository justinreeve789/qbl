Backups, copies and the starship hub

Three ways to get a whole scenario at once, all on the editor's Scenarios page (and Export and Duplicate again under a scenario's Settings).

Starting aboard the starship

New scenario asks for a title and how to start:

  • Start aboard the starship (the default): the new scenario begins as a copy of the starship hub.
  • Start empty: one blank scene.

The hub is the ship missions are launched from, without any mission: the control room, observation deck, laboratory, main corridor, crew quarters, hydroponics bay, engine room and marketplace, the doors between them, the things to read in each room, and:

  • The crew: Captain Vega in the control room, Chief Engineer Okoro in the engine room, Botanist Lin in hydroponics and Quartermaster Pax in the marketplace. Clicking one runs an indirect event in which they speak in a story box.
  • Things that go on by themselves: a planet drifts past the observation deck every couple of minutes (a wide, mostly empty picture scrolling as a background layer between the stars and the window frame), and a warning light blinks in the engine room (a start event: show a picture for a moment, wait, repeat).

The copy is the scenario's own. Every scenario therefore has the same ship to begin with, and each is free to change what happens aboard: add events to the rooms, change what the crew say, add the places the mission goes to and doors that lead there. Changing one scenario's ship changes no other. The pictures themselves are not copied: every copy uses the shipped files under /scenario-assets/.

The hub's rows are apps/api/database/seeders/data/hub.php, generated by php tools/make-hub.php from the demo's ship scenes (the lists at the top of that script say what is kept). Its two ambient pictures are made by tools/make-hub-art.py.

Duplicating

Duplicate makes a copy of a scenario as a new draft that belongs to you, with a new code and "Copy of ..." as its title. Everything is copied: scenes, events, actions, conditions, labels, media (uploaded files are copied into the new scenario's own folder), items, characters, variables, the scenario's own shop items, objectives and settings. Nothing is shared with the original afterwards, so a teacher can change text, add scenes, award extra stars or rebuild the mission without affecting anyone else. Players' saves and assignments are not copied.

  • A scenario you can edit is copied as it is in the editor now.
  • Public missions by others are listed under your own scenarios. They cannot be edited, but Make my own copy copies the version that is published. Private scenarios are not offered.

Export and import

Export downloads the scenario as one ZIP file:

File Contents
scenario.json The scenario document, exactly as these pages describe it
assets/ The files uploaded for the scenario. A media entry whose filepath ends in one of these names uses that file
README.txt What the file is and when it was made

Import a ZIP creates a new scenario from such a file: a draft with a new code, owned by whoever imported it. It never replaces an existing scenario, so a backup can always be brought back beside the scenario it was made from.

What does not travel: media that was not uploaded keeps its address and is loaded from there (the demo's pictures under /scenario-assets/ are part of every installation); shop items that were switched off are not in the JSON; avatars, players' saves, assignments and the published state.

Making a ZIP by hand

Any ZIP with a scenario.json (at the top, or inside one folder) is accepted, so a scenario can be written as JSON, or generated, and brought in whole.

  • Ids only have to be consistent within the file: every row gets a new id on import and references follow (media_id, scene_id, target_event_id, target_id, item_id, character_id, a label's media, and so on). Parts without an id are given one.
  • A media entry's file is looked for in the ZIP by the file name its filepath ends in, then by its url, then by its filename, under assets/ or beside scenario.json. A file found becomes an uploaded file of the new scenario; an entry with no file in the ZIP keeps its url.
  • jump_targets and session are ignored (the first is generated; the second is a player's). avatar_media_ids and avatar_portraits are dropped: avatars are the platform's.
  • Only pictures (PNG, JPEG, WebP, GIF), sound (MP3, WAV, OGG) and video (MP4, WebM) are accepted, judged by content, each up to 25 MB. A ZIP holding a file of another kind where a media file is expected is refused whole.

The imported scenario is a draft. Open it and press Publish: the checks there say if anything in the file does not add up.

Help icons

Explanations in the editor are behind a small ? beside the field, heading or page title they belong to. Click it (or focus it and press Enter) to read the explanation; click anywhere or press Escape to put it away. Hovering shows the same text as a tooltip.
